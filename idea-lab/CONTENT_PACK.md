## The Foundry — glossary (clickable term cards)

Each entry: a one-line kid definition, then a deeper accurate explanation.

- **Silica / silicon dioxide (SiO₂)** — The hard, glassy stuff most sand is made of, silicon and
  oxygen joined together. *Deep:* SiO₂ is one silicon atom bonded to two oxygen atoms, repeated in a
  giant network. It is one of the most common compounds in Earth's crust and the main ingredient in
  quartz sand, glass, and quartz crystals. The silicon is locked to oxygen, so silica can't be used in
  electronics as-is; the oxygen has to be removed first to get pure silicon, the shiny gray
  semiconductor that chips are made from. [en.wikipedia.org/wiki/Silicon_dioxide]
- **Quartz** — A hard, see-through crystal that is just silica grown into a neat, repeating pattern.
  *Deep:* Crystalline SiO₂, one of Earth's most abundant minerals; its atoms line up in an orderly 3D
  pattern. Melt it and cool it without that order and you get glass; weather it into grains and you get
  much of the world's sand. [en.wikipedia.org/wiki/Quartz]
- **Silicon** — A shiny grey material we pull out of sand and use to make computer chips. *Deep:*
  Element Si (atomic number 14). In nature it is almost always combined with oxygen as silica, not
  found pure. Strip the oxygen in a furnace and you get solid silicon, a brittle grey semiconductor,
  which is exactly the property that makes it useful for transistors. [en.wikipedia.org/wiki/Silicon]
- **Semiconductor** — A material that can be switched between letting electricity flow and blocking it.
  *Deep:* Conducts better than an insulator (glass) but worse than a metal (copper), and its
  conductivity can be changed on demand. Doping and applied voltages make it switch current on or off,
  the basis of every transistor and chip. [en.wikipedia.org/wiki/Semiconductor]
- **Doping** — Mixing in a tiny pinch of another element so silicon carries electricity the way we
  want. *Deep:* Adding a small impurity (phosphorus or boron) to pure silicon to control how it
  conducts. Phosphorus adds spare electrons (n-type); boron makes "holes" (p-type). Often about one
  dopant atom per ten million silicon atoms. [en.wikipedia.org/wiki/Doping_(semiconductor)]
- **Wafer** — A thin, round slice of silicon crystal that chips are built on. *Deep:* A polished disc
  cut from a single silicon crystal (ingot). Thousands of identical chips are built across one wafer at
  once, then cut apart. Modern wafers reach 300 mm (about 12 inches) across.
  [en.wikipedia.org/wiki/Wafer_(electronics)]
- **Transistor** — A tiny electric switch with no moving parts: a small voltage turns a bigger flow of
  electricity on or off. *Deep:* In a MOSFET, a gate voltage forms or removes a conducting channel,
  controlling current without the gate drawing current. It flips billions of times per second, and one
  chip holds billions of them. [en.wikipedia.org/wiki/Transistor]
- **Logic gate** — A tiny circuit that takes on/off inputs and follows a rule to decide its output.
  *Deep:* Built from a few transistors. AND outputs 1 only when both inputs are 1; OR when at least one
  is. Combine many and a computer can add, decide, and remember. [en.wikipedia.org/wiki/Logic_gate]
- **Bit** — The smallest piece of computer information: a single on/off, 1 or 0. *Deep:* Short for
  "binary digit." Inside a chip a bit is a voltage high or low. Group them and you get everything: 8
  bits make a byte. [en.wikipedia.org/wiki/Bit]
- **Piezoelectricity** — Squeezing certain crystals (like quartz) makes a jolt of electricity, and
  electricity makes them squeeze back. *Deep:* Squeezing shifts the crystal's charges out of balance,
  creating a voltage; a voltage makes it flex. Powers spark lighters, quartz-watch timing, ultrasound,
  and sonar. [en.wikipedia.org/wiki/Piezoelectricity]
- **Where silicon comes from** — Heat quartz sand with carbon in a super-hot furnace; the carbon pulls
  the oxygen away, leaving silicon. *Deep:* Carbothermic reduction in an electric arc furnace at
  ~1800–2000 °C. SiO₂ + 2C → Si + 2CO, giving ~98–99% pure "metallurgical-grade" silicon, purified
  much further before chips. Not burning (which adds oxygen); the carbon removes it.
  [en.wikipedia.org/wiki/Silicon#Production]
- **How a chip is made** — Grow one giant perfect crystal, slice it into wafers, then use light to
  print tiny circuit patterns. *Deep:* Czochralski growth: melt ultra-pure silicon (~1420 °C), dip a
  seed crystal, pull up slowly while rotating so it freezes as one crystal (ingot). Slice into wafers,
  then photolithography prints circuits (photoresist + patterned mask + etch), repeated 20–30 times to
  build billions of transistors. [en.wikipedia.org/wiki/Czochralski_method]

## The Foundry — logic gates (truth tables + code)

For the new gate puzzle (add NAND/NOR/XOR) and the "show me the code" view. All verified.

| Gate | Rule | Truth table |
| --- | --- | --- |
| NOT | flips the input | 0→1, 1→0 |
| AND | 1 only if both are 1 | 00→0, 01→0, 10→0, 11→1 |
| OR | 1 if at least one is 1 | 00→0, 01→1, 10→1, 11→1 |
| NAND | opposite of AND | 00→1, 01→1, 10→1, 11→0 |
| NOR | opposite of OR | 00→1, 01→0, 10→0, 11→0 |
| XOR | 1 when inputs differ | 00→0, 01→1, 10→1, 11→0 |

Code per gate (a = input, b = second input; 0/1):

```python
def NOT(a):   return 1 - a
def AND(a,b): return a & b
def OR(a,b):  return a | b
def NAND(a,b):return 1 - (a & b)
def NOR(a,b): return 1 - (a | b)
def XOR(a,b): return a ^ b
```
```javascript
const NOT  = a    => a ? 0 : 1;
const AND  = (a,b)=> a && b ? 1 : 0;
const OR   = (a,b)=> a || b ? 1 : 0;
const NAND = (a,b)=> a && b ? 0 : 1;
const NOR  = (a,b)=> a || b ? 0 : 1;
const XOR  = (a,b)=> a !== b ? 1 : 0;
```
```c
int NOT(int a){ return !a; }
int AND(int a,int b){ return a && b; }
int OR(int a,int b){ return a || b; }
int NAND(int a,int b){ return !(a && b); }
int NOR(int a,int b){ return !(a || b); }
int XOR(int a,int b){ return a != b; }
```
```java
static int not(int a){ return a==0?1:0; }
static int and(int a,int b){ return (a==1&&b==1)?1:0; }
static int or(int a,int b){ return (a==1||b==1)?1:0; }
static int nand(int a,int b){ return (a==1&&b==1)?0:1; }
static int nor(int a,int b){ return (a==0&&b==0)?1:0; }
static int xor(int a,int b){ return (a!=b)?1:0; }
```
Pseudocode (for the youngest): `IF a is 1 AND b is 1 THEN 1 ELSE 0` (and so on per rule).

Build-up expressions:
- `(a AND b) OR (NOT c)` → py `(a & b) | (1 - c)` · js `((a && b) || !c) ? 1 : 0`
- Two-switch staircase light (XOR) → py `a ^ b` · js `a !== b ? 1 : 0`

## The AI Wing — copycat detail cards

Each mode: how it really works (kid-friendly, accurate), then the real 2026 defense. No how-to.

- **Voice cloning** — *How:* AI listens to a few seconds of someone talking (even grabbed from a
  posted video) and learns the shape of their voice, then makes it say new sentences. On a phone call it
  can sound almost perfect. *Defense:* A voice is no longer proof. Hang up and call back on a number you
  already have. Agree on a family code word and ask for it. Rush and secrecy are red flags; real
  emergencies survive a one-minute check. [FTC voice-cloning alert 2024; FBI/CNN 2026]
- **Deepfake face / video** — *How:* AI can paste or puppet a face onto video, even live on a call,
  from a single photo. You usually can't be sure by staring, and hunting for "glitches" isn't reliable.
  *Defense:* Treat a face on screen like a voice, not proof. Verify on a separate trusted channel; ask
  something only the real person knows. [NSA/FBI/CISA "Contextualizing Deepfake Threats" 2023]
- **Writing-style mimicry** — *How:* AI reads how someone writes and copies their words, length, and
  tone to fake a boss's email or a friend's text. Clean spelling means the old "bad grammar" tell is
  gone. *Defense:* Sounding like someone isn't proof it's them. Confirm surprising or money requests on
  a channel you already trust. [FBI IC3 2025 report; IC3 PSA 2025]
- **AI photo generation** — *How:* AI makes brand-new photos of people or places that never existed,
  learned from millions of real images. They can look completely real, and detector tools get it wrong
  a lot. *Defense:* Check where it came from before believing or sharing. Reverse image search can find
  an earlier original. Look for Content Credentials (C2PA), a tamper-evident "where this came from"
  label now in some cameras and AI tools. No single check is perfect, so stack several plus a known
  source. [Content Authenticity Initiative / C2PA 2026; NSA/CISA Content Credentials CSI 2025]

## The Defense Range — glossary (clickable term cards)

- **Client-side vs server-side check** — Client-side runs on your computer where you can change it;
  server-side runs on the website's computer where you can't. *Deep:* Browser JavaScript is fully
  visible and editable by the visitor, so any rule it enforces can be bypassed. Only server-side checks
  can actually keep someone out; the real decision must be repeated on the server. [OWASP Input
  Validation Cheat Sheet]
- **Inspect Element / Dev Tools** — A built-in browser window to see and temporarily change any page's
  real code on your own screen. *Deep:* Reveals HTML/CSS/JS and lets you edit live, but the edits only
  affect your copy and vanish on reload, because they never reach the server. This is why a site can
  never trust what the browser sends back.
- **Brute-force guessing** — Trying every possible password until one works. *Deep:* Time grows
  extremely fast with length; guaranteed in theory, but for a long unpredictable password the count is
  impractical. [OWASP Brute Force Attack]
- **Dictionary attack** — A smarter attack that tries common words, leaked passwords, and predictable
  patterns first. *Deep:* Uses a wordlist plus rules (append 123 or !, swap letters for look-alikes), so
  p@ssw0rd doesn't help. It fails when the password is something a wordlist would never contain: random
  characters or unrelated words. The real key is being unpredictable, not just long.
  [OWASP OAT-007 Credential Cracking]
- **Password length and entropy** — Entropy measures unpredictability; each random character multiplies
  the guesses needed, so length beats squiggles. *Deep:* Length is an exponent, so it dominates. Caveat:
  the math assumes randomness, so a long but predictable password has far less real entropy than it
  looks. NIST recommends length over imposed complexity. [NIST SP 800-63B]
- **Passphrase** — Several random words strung together: long, hard to guess, easy to remember. *Deep:*
  Chain unrelated words (river-purple-engine-cloud). They must be random, not a famous quote. NIST
  encourages long memorized secrets and allows spaces and 64+ characters. [NIST SP 800-63B]
- **Password manager** — An app that makes, stores, and fills a different long password for every site.
  *Deep:* You remember one master password; it remembers the rest, encrypted, so every account is unique
  and one leak doesn't endanger the others. [NIST SP 800-63B]
- **Hashing (high level)** — A one-way scramble that turns a password into a jumble that can't be
  reversed, so the site checks you without storing your password. *Deep:* The site stores and compares
  hashes. Good practice salts each one and uses a deliberately slow function (bcrypt, scrypt, Argon2,
  PBKDF2) so guesses can't be tested quickly. [NIST SP 800-63B 5.1.1.2; OWASP Password Storage]
- **Phishing** — A fake message or site pretending to be someone you trust to fool you into typing your
  password. *Deep:* Social engineering via email/text that sends you to an imposter login page. No
  password strength helps, because you give the secret away; the defenses are recognizing fakes and
  phishing-resistant multi-factor auth. [CISA Recognize and Report Phishing]
